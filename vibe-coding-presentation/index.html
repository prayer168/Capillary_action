Vibe Coding 經驗分享

以「互動數位教材 skill」為案例，說明如何把需求、AI 協作、程式實作、驗證與 GitHub Pages 佈署串成可重複的工作流。

Agenda

今天不是只談「讓 AI 寫程式」

1定義Vibe coding 是什麼，不是什麼。
2原理需求、上下文、迭代、驗證如何形成閉環。
3工具Codex、Skill、瀏覽器、GitHub、靜態網站。
4實作用互動教材案例走一次完整流程。
5佈署把網頁交付到 GitHub Pages，並能持續修改。

Definition

Vibe Coding：把意圖轉成可運行成果的協作流程

它不是單純「請 AI 幫我寫一段程式」，而是用自然語言、範例、檔案、錯誤訊息和測試結果，持續校準 AI 的方向，直到產品真的能用。

核心判準

成果能否被打開、操作、檢查、修改、佈署，而不是回答看起來是否聰明。

Boundary

Vibe Coding 不是放棄工程判斷

常見誤解

  • 只要描述感覺，AI 就會完成所有事情。
  • 看起來有畫面，就等於功能正確。
  • 複製貼上答案，不需要理解檔案結構。
  • 不用測試，不用版本控制。

實際做法

  • 用具體需求與限制引導產出。
  • 讓 AI 讀專案、改檔、跑檢查。
  • 把錯誤、畫面、使用者回饋納入下一輪。
  • 用 Git 與佈署流程保留可回溯紀錄。

Mental Model

三層能力：說清楚、看現場、驗結果

01

需求表達

把目標、受眾、情境、限制、範例與成功條件講清楚。

02

上下文操作

讓 AI 讀檔案、理解現有架構、沿用風格、保留使用者原本修改。

03

驗證閉環

用語法檢查、瀏覽器、RWD、功能操作與線上頁面確認成果。

Loop

Vibe Coding 的基本循環

意圖
提示
實作
驗證
修正

真正的關鍵是「修正」：你不需要第一次就講完所有需求，但每一輪都要讓模型更接近可交付結果。

Principle

它可行，因為程式工作本來就很適合外部化

需求可文字化

功能、限制、元件、流程、資料格式都能用文字或範例描述。

成果可執行

網站、腳本、測試和錯誤訊息都能成為下一輪輸入。

品質可檢查

語法、互動、RWD、連結、佈署狀態都能被明確驗證。

Prompting

好的提示不是咒語，是壓縮後的規格

「我要做一個四年級自然課互動教材，主題是毛細現象。第一屏要能直接操作；學生可以調整材質、寬度、時間，看到水位上升；要 RWD；最後可佈署到 GitHub Pages。」

  • 受眾：四年級學生
  • 任務：互動教材，不是文章頁
  • 核心互動：材質、寬度、時間、水位
  • 限制：RWD、靜態網站、GitHub Pages

Context Engineering

上下文比單次 prompt 更重要

給 AI 的上下文

  • 目前資料夾與既有檔案。
  • 使用者剛建立的 skill。
  • 已存在的設計風格與頁面模式。
  • 錯誤訊息、截圖、測試輸出。

AI 應該回報

  • 它正在讀哪些檔案。
  • 它採用哪些既有規則。
  • 它改了哪些檔案。
  • 它跑了哪些驗證。

Skill

Skill：把你的偏好變成可重複流程

你建立的 skill 不是一般備忘錄，而是給 Codex 的工作規範：何時使用、先問什麼、怎麼設計、要建立哪些檔案、如何驗證、怎麼佈署。

name: build-interactive-science-lesson
description: Build, revise, document, and publish responsive
digital interactive science learning materials...

Why Skill

Skill 解決的是「每次都要重新交代」的問題

穩定風格

例如繁體中文、國小自然課、觸控友善、大字標籤、第一屏就是可用體驗。

穩定流程

先確認範圍、做設計摘要、建靜態檔、驗證互動、再佈署。

穩定品質

把常見失敗模式寫進規則，下一次模型就會主動避開。

Skill Anatomy

一個實用 skill 通常包含這些段落

Purpose說明這個 skill 要解決的任務。
Operating Rules語言、資料夾、版本控制、修改範圍。
Workflow從確認需求到建檔、驗證、佈署。

Checklist交付前要跑的檢查。

Tools

一場完整 Vibe Coding 會用到的工具

Codex讀專案、改檔、跑命令、協作迭代。
Skill保存你的工作規則與教學偏好。
PowerShell檔案搜尋、語法檢查、啟動本機伺服器。

Static Site

互動教材最常用的靜態網站結構

lesson-folder/
  index.html    # 結構與內容
  styles.css    # 視覺、RWD、投影或手機版
  script.js     # 互動、Canvas、資料、驗證
  README.md     # 使用方式、佈署說明
  .nojekyll     # GitHub Pages 靜態檔提示

這種結構適合老師分享、學生開啟、GitHub Pages 佈署，也方便日後讓 AI 做小幅修正。

Case Study

案例：用 Vibe Coding 建互動自然教材

教學主題毛細現象、連通管、保溫瓶或其他自然單元。
學習情境課堂投影、學生平板操作、小組觀察紀錄。
成果形式一頁式互動網站，包含模擬、資料輸入、圖表與測驗。
交付方式本機資料夾、GitHub repo、GitHub Pages 網址。

Step 1

先問少量關鍵問題，不把老師拖進技術細節

  • 年級、單元、課堂使用方式是什麼？
  • 學生要自己操作、老師投影，還是小組活動？
  • 是否有影片、逐字稿、教材 PDF、圖片或參考網站？
  • 需要模擬、圖表、測驗、學習單、教師備註嗎？
  • 最後要放在哪個資料夾、哪個 GitHub repo？

Step 2

先產生設計摘要，讓方向可確認

標題四年級自然：觀察毛細現象
目標看見水在細縫或纖維中上升，理解材料與寬度的影響。
頁籤實驗室、資料紀錄、生活應用、小測驗。
互動滑桿控制寬度與時間，按鈕重播水位上升動畫。
RWD桌機並排比較，手機改為上下堆疊與大按鈕。

UX Principle

第一屏就要能用，不要先做說明頁

Vibe coding 的提示可以直接指定：「不要做 landing page，第一畫面就是學生操作區」。

Patterns

互動教材常用模式

比較實驗

兩種材料並排，學生直接比較結果，不藏在下拉選單裡。

滑桿控制

寬度、層數、時間、距離等連續變因用 slider 表示。

資料圖表

學生輸入觀察值，圖表立即更新，單位保持一致。

Canvas 模擬

用動畫呈現肉眼不易觀察的概念變化。

Example Code

範例：讓滑桿更新模擬數值

const widthSlider = document.querySelector("#tubeWidth");
const result = document.querySelector("#riseHeight");

function calculateRise(width, materialFactor) {
  return Math.round((materialFactor / width) * 100);
}

widthSlider.addEventListener("input", () => {
  const height = calculateRise(Number(widthSlider.value), 1.8);
  result.textContent = `${height} cm`;
  drawCapillaryScene(height);
});

Canvas

Canvas 最容易踩雷：隱藏頁籤與尺寸

問題

Canvas 在隱藏 tab 裡初始化，寬高可能是 0，切換後會空白。

處理

第一時間畫出可見 frame，tab 切換與 resize 後重新計算尺寸再 redraw。

驗證

確認 canvas 寬高非 0、畫面非空白、console 沒錯誤。

Responsive

RWD 不只是縮小，是改變操作密度

桌機 / 投影並排比較、較大圖表、老師可遠距離講解。
平板保留兩欄或改成上下區塊，按鈕需適合觸控。
手機單欄、短標籤、控制項寬度固定，避免文字擠壓。

Validation

交付前要讓 AI 真的檢查

語法node --check script.js
文字一致年級、單元、單位、標題、metadata 全部搜尋。
互動tab、slider、quiz、reset、chart、canvas 都操作一次。
RWD桌機、平板、手機寬度檢查不重疊、不溢出。
佈署線上頁面用 cache-busting query string 驗證。

Live Build Flow

一次實作可以這樣跑

  1. 讀 skill 與現有專案，確認可沿用的規則。
  2. 建立資料夾與靜態檔案。
  3. 先完成第一屏互動，再補頁籤與內容。
  4. 加入資料輸入、圖表、動畫與測驗。
  5. 跑語法檢查與瀏覽器視覺檢查。
  6. 修正問題後提交 Git 並佈署。

Conversation

你可以這樣指揮 AI

老師：第一頁太像介紹頁，學生打開後還不知道要做什麼。

AI：我會把實驗操作區移到第一屏，保留標題但縮短說明，並把「開始觀察」設為主要動作。

老師：手機上按鈕擠在一起。

AI：我會針對 390px 寬度調整控制列，固定按鈕高度，讓標籤換行但不擠壓圖表。

Failure Modes

你的 skill 已經把常見失敗寫進去

改錯資料夾

先看路徑、時間、Git 狀態與遠端 repo，再修改。

Canvas 空白

可見 first frame、tab activation redraw、resize redraw。

RWD 假正常

量 scrollHeight 與 viewport，不只目視檢查。

單位漂移

從 HTML、JS、README、metadata 到圖表標籤都要搜尋。

Version Control

Git 是 Vibe Coding 的安全網

git status
git diff --stat
git add index.html styles.css script.js README.md
git commit -m "Build interactive science lesson"
git push origin main

重點不是背指令，而是每次只提交這次任務相關的檔案，保留可回溯紀錄。

Deployment

網頁佈署：GitHub Pages 最適合靜態教材

  1. 建立 GitHub repository。
  2. 把網站檔案推到 main 分支。
  3. 在 Settings → Pages 選擇來源為 main 與根目錄。
  4. 等待 Pages 建置完成。
  5. 打開網址並加上 ?v=日期時間 確認不是舊快取。

After Deploy

線上成功不等於交付完成

Demo Prompt

現場示範可以從這段開始

請依據我的 build-interactive-science-lesson skill，建立一個四年級自然課互動教材。主題是「保溫瓶如何減少熱散失」。第一屏要能直接操作三種保溫結構，學生可以切換材料、調整時間，看到溫度下降曲線。請建立 index.html、styles.css、script.js、README.md，並完成 RWD 與語法檢查。

Demo Breakdown

把示範拆成 AI 能執行的小任務

需求四年級、保溫瓶、熱散失、第一屏可操作。
模型材料影響降溫速度，時間推進曲線。
畫面瓶身剖面圖、材料切換、溫度圖表。
驗證slider 能更新、圖表重繪、手機不重疊。
佈署Git commit、push、Pages、線上驗證。

Collaboration

老師與 AI 的分工

人負責

  • 判斷學習目標是否正確。
  • 決定學生要觀察什麼。
  • 指出畫面是否符合課堂情境。
  • 確認語言與教學難度。

AI 負責

  • 把需求轉成檔案與程式。
  • 搜尋並修改一致的文字與單位。
  • 重複執行檢查與修正。
  • 整理 README、Git 與佈署流程。

Takeaways

聽眾最需要帶走的 5 件事

  1. Vibe Coding 是可驗證的協作流程，不是神奇 prompt。
  2. Skill 能把個人經驗轉成 AI 可遵守的工作規範。
  3. 互動教材要從「學生第一眼能操作」開始設計。
  4. 每一次修改都要跑檢查，尤其是 RWD、Canvas 與線上快取。
  5. GitHub Pages 讓作品從本機檔案變成可分享教材。

Closing

Vibe Coding 的真正價值：把想法變成可迭代作品

當我們把教學目標、設計偏好、驗證清單與佈署流程寫進 skill，AI 就不只是回答問題，而是成為能跟著你工作方式前進的製作夥伴。
